# Kokugakuin ranking anomaly review — scope & routing design (2026-07-08)

Emma's wiki-queue ask: "comprehensive review of some of the anomalies in
kokugakuin university shrine rankings … agentic rag or reasoning could either
make the content normalized or declare it as intentionally that way."

The anomaly catchers and their live output (all in
`modern-quickstatements/p958_manual_review.txt`, regenerated by
`generate_p958_qualifiers.py` each CI run, plus the ranking generator's
duplicate reports):

## 1. Ranking sequence anomalies — 7 parents

Parents whose P527/P460 candidates carry non-sequential P1352 rankings, e.g.
`rankings=[2], expected=[1]` (a gap — candidate removed/merged?) or
`rankings=[0,0,0,3,4], expected=[0,1,2,1,2]` (Nimasukarakuniitateno Shrine —
possibly two ranking SERIES flattened into one).

**Answer semantics for RAG routing:** per parent, either
`RENUMBER: Qcand=1, Qcand2=2, …` (collector emits P1352 qualifier updates —
NOTE: updating an existing qualifier value is remove+re-add territory, NOT
drip-safe; route through a browser batch for Emma) or `INTENTIONAL: <why>`
(weird-is-signal: Emma's structures are often deliberate — e.g. rank-0
"disproven" candidates coexisting with ranked ones may be by design).

## 2. Multiple P13677 — ~85 rows

Items carrying 2+ Kokugakuin Museum entry IDs (an item that IS the identified
shrine for several distinct Engishiki entries), where the P958 (section)
qualifier on the parent-link must say WHICH entry backs the link.

**Answer semantics:** per (item, parent) row, the correct P13677 entry id →
collector emits `parent|P460|item|P958|"<section>"` qualifier-adds
(add-only, drip-safe). The worker needs the item's P13677 values (fetch into
the work-file) and the parent's Engishiki identity to match entry↔parent.

## 3. Duplicate-property reports (context, probably NOT this review)

The ranking generator also reports duplicate P361 (386 items), P1448 (105),
P6375 (252). These are general data-hygiene, not ranking anomalies; they
predate today and drain separately. Not in scope unless Emma says otherwise.

## Routing plan (next session)

Clone the ronsha_ranking_review pattern: builder parses
`p958_manual_review.txt` → work-files in `kokugakuin_anomaly_review/`
(7 sequence + ~85 multi-entry, with fetched P13677 values inline), section
registered in `remote_queue.py`, collector splits: INTENTIONAL → log;
RENUMBER → browser batch file for Emma; P958 answers → ATOMIC qualifier-adds.
Nothing here is buildable-with-confidence at 01:00 — the answer formats above
are the design; execute fresh.
