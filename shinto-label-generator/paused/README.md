# Paused label output — not in the drip

Files here are **generated label proposals that are deliberately NOT being submitted**. They sit
outside `shinto-label-generator/quickstatements/` for one mechanical reason:
`modern-quickstatements/select_label_proposals.py` builds the daily drip by
`QS_DIR.glob("*.txt")` over that directory and pools the raw lines, ignoring filenames. Anything in
there goes out. Moving a file here is the way to stop it without deleting the work.

## What is NOT here any more (2026-09-18)

`religious_building_ja.txt`, `_zh`, `_ko` and `stage1_en_replacements.txt` were here and are now in
`quickstatements/`, on the daily drip like every other language file.

They should never have been here. Emma: *"why is all of this shit paused instead of part of the
pipeline as expected"*. I had offered "output to paused/ for review first" as an option early in the
build and it stuck, which turned ordinary generated output into something needing a human to
release it — the gated-on-a-human-reviewing failure CLAUDE.md names directly. **Only a file with a
real defect belongs in this directory**, and only one has one.

⛔ **A bug caught on the way in, worth keeping.** `stage1_en_replacements.txt` carried its
provenance inline after a TAB:

    Q105241345|Len|"Church of the Resurrection"	# was: Auferstehungskirche

`select_label_proposals.py` does `s.replace("	", "|")` when it pools a line, so that comment would
have become a **QuickStatements field** and all 16 lines would have been malformed commands. The
generator now writes QS lines only and puts provenance in `stage1_en_replacements.log`, here.

## ⛔ Do not "re-open" the pause by widening stage 1's intake (2026-09-19)

A queue item asked to **drop the Latin-script gate in stage 1 and transliterate
Arabic/Hebrew/Devanagari Commons categories into English labels**, on the reasoning that
the gate is "why there are no Arab-world mosques and no Hebrew-named synagogues at all:
not refused downstream, never selected."

Measured, it is wrong four ways, and the answer is recorded in the generator's own
docstring so a third session does not re-derive it:

* **The gate rejects 2 items.** The 2026-07-11 run: 22,644 candidates, **2** non-Latin
  Commons names skipped (DEVLOG 2026-07-11). 0.009%.
* **16 Arab-world mosques and 451 synagogues are already selected** — Saudi 4, Egypt 3,
  Palestine 2, UAE 2, Iran 2, Oman, Tunisia, Yemen. The few that go no further are
  refused *downstream* by `plain_latin_katakana.rules_for_country`, deliberately.
* **Arabic and Hebrew do not romanise derivably** — both omit short vowels, so the
  romaniser invents them: `مسجد النور` → `masajada alanav̈ara`.
* **It widens the exact intake that caused this pause.** An English label transliterated
  out of an Arabic Commons category is further from "an authoritative English source"
  than the German strings that stopped it.

⭐ **A live bug found on the way**: the pause moved this file with `git mv` and unwired
CI, but `generate_religious_building_labels.OUT` still pointed at `quickstatements/`. A
hand-run would have written all 22,548 paused labels back into the drip directory.
`test_no_workflow_regenerates_a_paused_file` cannot see that, because a hand-run is not
a workflow; `test_the_output_path_is_the_paused_directory` now does.

## `religious_building_en.txt` — paused 2026-09-17

22,548 English labels for churches, cathedrals, chapels, mosques and synagogues, generated by
`generate_religious_building_labels.py` and live in the drip until today.

**Why it stopped.** Emma, 2026-09-17: *"This is a complex task involving possibly 50 separate
decisions and imposing ontology on all religious buildings. Earlier sessions underestimated the
difficulty and used wikimedia commons as the only source like it was somehow authoritative."*

The generator takes the item's Commons category (P373), checks it is Latin script, and uses it
verbatim as the English label. Measured over all 22,548 lines, that premise does not hold:

| | |
|---|---|
| labels with **no English type word at all** | **15,001 (67%)** |
| Church | 5,147 |
| Chapel | 1,652 |
| Synagogue | 389 |
| Monastery | 167 |
| Mosque | 154 |
| Cathedral / Temple / Basilica / Abbey | 38 |

A Latin-script Commons category is frequently not English — `Kirche Rehden`, `St.-Petri-Kirche`,
`Jerusalemkirche`, `San Giovanni Battista`, `Madonna del Pero` — so these are German and Italian
strings being written into `en` labels. The script-check only ever asked whether the characters were
Latin, never whether the string was English.

⚠ **Some of these already reached Wikidata**, because the file was in the drip pool from whenever it
was first generated until 2026-09-17. Nothing here reverts those; pausing only stops more going out.

**It is also unwired from CI** — the `label-generator-regenerate.yml` step that would refresh it was
removed in the same commit. The generator still exists and still runs by hand.

**To resume:** move the file back into `shinto-label-generator/quickstatements/`. Nothing else is
needed, which is exactly why `tests/test_paused_labels_stay_out_of_the_drip.py` pins it.
